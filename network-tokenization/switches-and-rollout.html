Switches and rollout: who decides if a network token is used

Two switches decide the outcome: one in PGW, one at the gateway. They do different things on MPGS and on CyberSource. The PGW switch is a safety switch for the rollout, per MID, default OFF.

IllustrativeReflects PGW dev stories v1.1 · 19-Nov-2026Rule 1: master togglePrerequisites P1–P3

The switches

PGW configuration · per MID · default OFF

Generate and Use Network Token

The one master toggle for all NT work (Rule 1). Exists today; v1.1 gives it this meaning. A later release can remove it.

PGW configuration · existing, unchanged

Enable tokenization, CIT, MIT

Enable tokenization, CUSTOMER_INITIATED_TRANSACTIONS, MERCHANT_INITIATED_TRANSACTIONS still apply as today.

MPGS · per MID and token repository (P1)

Network tokens on MPGS

MDES onboarding, Visa VTS via an existing TRID, Enable Network Tokens per merchant. Set by the merchant integration team.

CYBS · per MID (P2)

Token permission on CYBS

Network token provisioning on the vault; Visa and Mastercard token permission per MID.

PGW configuration · not used

Use Network Token, Send NT to merchant

Exist from an earlier project. Not used in this release.

Rollout

  1. Release with the toggle OFF on every MID.

    PGW behaves exactly as today: no instrument identifiers, CYBS CIT and MIT with the card number, networkTokenDetails = null.

  2. Switch ON for the production test MID and test in production.

    Without the toggle, a fault would hit every card-on-file merchant at release and the only fix would be a code rollback.

  3. Switch ON per card-on-file MID.

    The MID list is reviewed with Business and Risk & Compliance first. Gateway set-up (P1, P2) must be in place for the MID.

  4. New card-on-file merchants: network tokens are mandatory.

    Agreed in the 19-Nov mandate alignment meeting.

  5. A later release removes the toggle.

    Network tokens then apply wherever save card, CIT or MIT is enabled.

Partners that connect to the gateway directly

On Geidea's MSO

Geidea switches network tokens on for their MIDs at the gateway, sends an advisory, and spot-checks their CIT and MIT. The PGW toggle does not apply: these partners do not pay through PGW.

On their own MSO

Risk & Compliance sends an advisory. The partner generates and uses network tokens on its own set-up.
