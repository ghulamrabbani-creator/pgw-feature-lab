Network Tokenization — PGW Dev Stories (MPGS and CyberSource)

Version 1.1 · 19-Nov-2026 · Prepared by Ghulam Rabbani (Product) Team: PGW engineering team

Changes in v1.1 (19-Nov-2026): Rule 1 now uses one master toggle, Generate and Use Network Token, per MID, default OFF. NT-C1: one CYBS call only (no enrollment call), no securityCode, adapter returns failures, no secrets in logs. NT-0 acceptance criterion 5 added.

These stories are the requirement. Each story can be read alone. A story refers to another story only for work that must be built first.

Rules for every story

Switches and rollout
  1. Master toggle. The existing PGW configuration parameter Generate and Use Network Token is the one master toggle for all work in these stories. It is set per MID. Default: OFF for all MIDs.
    • Toggle OFF: PGW behaves exactly as today. PGW does not create CYBS instrument identifiers. PGW pays CIT and MIT on CYBS with the card number. PGW sets networkTokenDetails = null. PGW does not change the Geidea token record.
    • Toggle ON: the stories apply. The existing toggles still apply as today: Enable tokenization, CUSTOMER_INITIATED_TRANSACTIONS, MERCHANT_INITIATED_TRANSACTIONS.
    • Do not use the other network token parameters (Use Network Token, Send NT to merchant).
    • Rollout: switch ON for the production test MID, test in production, then switch ON for all merchants. A later release can remove this toggle.
    • MPGS: MPGS configuration per MID (P1) decides if MPGS pays with a network token. The PGW toggle controls only what PGW records. CYBS: the PGW toggle controls instrument identifier creation and payment with it. CYBS token permission per MID (P2) decides if CYBS uses a network token.
  2. A failure to read or record network token data never changes the payment result. Log the failure. Continue.
  3. Never store or log a full card number or a full network token number.
  4. Gateway field names are as in MPGS REST API version 80 and CyberSource REST API. PGW field names are camelCase.
  5. New fields in merchant APIs are additions. Do not change or remove existing fields.
  6. Copy gateway values as received, unless a rule in the story says otherwise.

NT-0 — Network token data model and merchant APIs

What PGW records

Background

Visa charges a fee on card-not-present transactions that do not use a network token. PGW does not record if a transaction used a network token. PGW does not record if a saved card has a network token.

Goal

  1. PGW has one object to record network token data on each transaction, for MPGS and CYBS.
  2. PGW returns this object to the merchant.
  3. The Geidea token record has fields for network token data and token status.

Story summary

This story adds the object and the fields. It does not fill them. The gateway stories (NT-M1 to NT-M5, NT-C1 to NT-C5) fill them.

Item Value
Story ID NT-0
Consumers Merchants (order inquiry, callback, pay responses). PGW stories NT-M1 to NT-C5.
Gateway API used None
Entities written transactions[].networkTokenDetails; Geidea token record
Depends on —
Followed by NT-M1 to NT-M5, NT-C1 to NT-C5
Out of scope Filling the fields (gateway stories). Token status logic (NT-X).

Requirements

1. New transaction object networkTokenDetails

Field Type Values Meaning
isNetworkToken Boolean true / false true = the gateway paid with a network token.
tokenProvider String VTS / MDES / null Network token provider. VTS = Visa. MDES = Mastercard. null when isNetworkToken = false.
maskedTokenNumber String e.g. 489537xxxxxx0001 (MPGS), 5222220000000000 (CYBS) / null Masked network token number. CYBS returns only the token BIN, so the rest is zero-filled.
tokenExpiryMonth String e.g. 11 / null Network token expiry month.
tokenExpiryYear String e.g. 28 / null Network token expiry year.
paymentAccountReference String e.g. V0010000000000000000000000001 / null PAR. One value per card.

2. Transactions that carry the object

  1. Add the object to transactions of type Pay, Authorization, Capture, Refund, Void.
  2. Do not add the object to Authentication transactions.
  3. Before a gateway story fills the object, set it to null.
  4. Transactions created before this release: networkTokenDetails = null.

3. Return the object to the merchant

Merchant API Where
Order inquiry GET /pgw/api/v1/direct/order/{orderId} order.transactions[].networkTokenDetails
Callback to callbackUrl order.transactions[].networkTokenDetails
POST /pgw/api/v2/direct/pay response order.transactions[].networkTokenDetails
POST /pgw/api/v2/direct/pay/token response order.transactions[].networkTokenDetails

4. New fields on the Geidea token record (internal)

Field Type Values Default (new and existing tokens) Meaning
schemeTokenProvider String VTS / MDES / null null A network token exists for this saved card. null = none seen yet.
tokenStatus String ACTIVE / INACTIVE ACTIVE For NT-X. Not read or changed in this release.
tokenStatusReason String free text null For NT-X. Not changed in this release.
tokenStatusDate DateTime UAE time null For NT-X. Not changed in this release.
cybsInstrumentIdentifierId String 19 digits / null null CYBS instrument identifier. Set by NT-C1.
networkTokenState String e.g. ACTIVE / null null Network token state from CYBS. Set by NT-C1.

Do not return the token record fields in any merchant API in this release.

5. Update rules

Field Rule
networkTokenDetails Write once per transaction. Do not update after that.
schemeTokenProvider When it is not null, do not change it.
tokenStatus, tokenStatusReason, tokenStatusDate Do not change in this release.

Acceptance criteria

  1. Order inquiry for an existing order returns networkTokenDetails = null on each Pay, Authorization, Capture, Refund, Void transaction.
  2. Authentication transactions do not have the object.
  3. Existing Geidea tokens have tokenStatus = ACTIVE and all other new fields = null.
  4. Existing merchant API fields do not change.
  5. Generate and Use Network Token OFF on a MID: networkTokenDetails = null on all new transactions. The Geidea token record does not change.

NT-M1 — Update MPGS token generation

Explorer: MPGS save card

Background

On MPGS, PGW creates an MPGS token after a card is saved. When network tokens are enabled on MPGS (P1), MPGS asks Visa or Mastercard for a network token for the card. The MPGS token response shows if a network token exists. PGW does not read this today.

Goal

PGW records on the Geidea token record if a network token exists for the saved card.

Story summary

Item Value
Story ID NT-M1
Gateway MPGS, API version 80
MPGS API used Create or update token: PUT /api/rest/version/80/merchant/{merchantId}/token/{tokenId}
Entities written Geidea token record: schemeTokenProvider
Depends on NT-0
Followed by NT-M3, NT-M4
Out of scope Payment requests and responses (NT-M2 to NT-M5). Token status (NT-X).

Requirements

1. Trigger

No change. PGW calls the MPGS token endpoint at the same point as today (SendToken, after a save-card payment).

2. Request

No change.

3. Response fields to read

MPGS field Type Example Meaning
schemeToken.provider String VTS A network token exists. Absent if none exists yet.

Note: in version 80 the token response has no masked network token number, no token expiry and no network token status.

4. Processing

# Condition Action
4.1 schemeTokenProvider on the Geidea token is not null Do not change it. Stop.
4.2 schemeToken.provider = VTS or MDES Set schemeTokenProvider = the value received.
4.3 schemeToken.provider is absent Leave schemeTokenProvider = null.
4.4 schemeToken.provider has any other value Leave schemeTokenProvider = null. Log the value.
4.5 The MPGS token call fails No change from today.

Why 4.3: MPGS can create the network token after the token call. NT-M3 and NT-M4 set schemeTokenProvider at the first payment with a network token.

Acceptance criteria

  1. Save a Visa card on an MPGS MID with network tokens enabled. Token response has schemeToken.provider = VTS. Geidea token has schemeTokenProvider = VTS.
  2. Same for Mastercard: MDES.
  3. MID without network tokens enabled: schemeTokenProvider = null.
  4. Save the same card again (same tokenId): schemeTokenProvider does not change.

NT-C1 — Create CYBS instrument identifier

Explorer: save card (T1)On demand (T2)Failure

Background

On CYBS, PGW does not create a gateway token when a card is saved. PGW sends the card number from the Geidea vault on each CIT and MIT. CYBS cannot use a network token this way. A CYBS instrument identifier links the card to a network token. A POC on 11 Nov 2026 (MID TEST-CYBS-01) confirmed: CYBS creates the network token with the instrument identifier, and payments with it use the network token.

Goal

PGW creates a CYBS instrument identifier for each saved card on CYBS and stores it on the Geidea token.

Story summary

Item Value
Story ID NT-C1
Gateway CyberSource REST API (Token Management Service)
CYBS API used POST /tms/v1/instrumentidentifiers
Entities written Geidea token record: cybsInstrumentIdentifierId, networkTokenState
Depends on NT-0
Followed by NT-C3, NT-C4
Out of scope Payment requests (NT-C2 to NT-C5). Creating the identifier inside the payment (actionList: ["TOKEN_CREATE"]): not used. CYBS customer and payment instrument tokens. Network token lifecycle updates from CYBS.

Requirements

1. Triggers

# Trigger When
T1 After save card A Pay or Authorize with save card is approved on a CYBS MID, and PGW saves the card. Same point as SendToken on MPGS.
T2 On demand NT-C3 or NT-C4 calls it before a CIT or MIT when cybsInstrumentIdentifierId = null. This covers cards saved before go-live and failed T1 calls.

2. Pre-checks

# Check On failure
2.1 The MID is routed to CYBS. Do not call CYBS. No error to the merchant.
2.2 Enable tokenization is ON for the MID. Do not call CYBS. No error to the merchant.
2.2a Generate and Use Network Token is ON for the MID. Do not call CYBS. No error to the merchant.
2.3 The card number and expiry are available in the Geidea vault for this token. Do not call CYBS. Log. No error to the merchant.

3. Request

CYBS field M/O/C Value
type M enrollable card
card.number M Card number from the Geidea vault
card.expirationMonth M 2 digits, e.g. 02
card.expirationYear M 4 digits, e.g. 2029
card.securityCode — Do not send. 
{ "type": "enrollable card",
  "card": { "number": "<PAN>", "expirationMonth": "02", "expirationYear": "2029" } }

Headers: the same as PGW payment calls on the MID: v-c-merchant-id, v-c-date, Digest, Signature (HTTP Signature, HmacSHA256), Content-Type: application/json. No profile-id header. (Proven in the 11-Nov POC, Postman collection "CYBS NT POC", request 2.)

HTTP status:

Status Meaning Action
201 New instrument identifier created Success (section 5)
200 Instrument identifier already exists for this card Success (section 5)
Any other Failure Section 5.3

This is the only CYBS call in NT-C1. Do not call POST /tms/v1/instrumentidentifiers/{id}/enrollment or any other TMS endpoint. (Test log 18-Nov-2026: the Cybersource adapter sent this extra call. CYBS rejected it with HTTP 400 invalidFields, card.number.)

4. Response fields to read

CYBS field Type Example Meaning
id String (19 digits) 7000000000000000001 Instrument identifier. CYBS generates it. PGW cannot set it.
tokenizedCard.state String ACTIVE Network token state at creation.

5. Processing

# Outcome Action
5.1 Success, id received Save id in cybsInstrumentIdentifierId. Save tokenizedCard.state in networkTokenState (null if absent).
5.2 Success, id differs from the stored value Replace the stored value. Log the old and new value.
5.3 Failure (timeout, HTTP 4xx, HTTP 5xx) Leave cybsInstrumentIdentifierId = null. Log the error. Do not change the result of the payment (T1). Return "not created" to the caller (T2). The Cybersource adapter returns the failure to PGW. It does not return a success code (000) when a CYBS call fails.

Note: the same card gives the same id. The CYBS test bench showed instrumentidentifierNew = true for a new card and false for a known card.

6. Sensitive data

  1. Read the card number from the vault only for this call.
  2. Do not log the request body.
  3. Do not log the merchant SharedSecretKey, MerchantKeyId or the CVV.

Acceptance criteria

  1. Save a Visa card on MID TEST-CYBS-01: Geidea token gets a 19-digit cybsInstrumentIdentifierId and networkTokenState = ACTIVE.
  2. Same for Mastercard.
