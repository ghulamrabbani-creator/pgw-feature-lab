Open point 1: no token permission on CYBS

TO VERIFY · PGW engineering team, during buildOpen point 1

With the PGW toggle ON, PGW creates an instrument identifier and pays with it and networkTokenOption = prefer. On a MID without CYBS token permission (P2), the payment must go out as the card, so P2 stays the control. CYBS documentation says prefer falls back to the card. This is not tested on a Geidea MID yet.

Guest checkout: tokenize before pay

IN POC · not a work item

Phase 1 covers saved cards (CIT and MIT). Visa's PAN Integrity Fee also applies to guest-checkout Visa payments that are not network-tokenized (from 17-Oct-2026 in the UAE). Visa's answer for guest checkout is Click to Pay. A POC on MPGS tests another route: create the gateway token for every new card before the payment, so the first payment can already go out with a network token.

The question: can the network token exist in time when the payment follows straight after the token is created?

run 1 · repository provisioning: asynchronous
tokenpay 0.6 s: CARDNT ~30 s

Payment approved but sent with the card number. The network token (VTS) appeared about 30 seconds later. Asynchronous provisioning loses the race.

Card number
run 2 · repository provisioning: attempt synchronous
token + NT ~1 spay: SCHEME_TOKEN

Token creation took about 1 second and returned with the network token. The payment straight after went out as SCHEME_TOKEN.

Network token
Context. Geidea e-commerce payments run 3DS, so in a real flow the customer's 3DS time sits between token creation and payment. Visa test card, MPGS test MID TEST-MPGS-01, 25-Nov-2026. Not tested on CyberSource. Whether this meets the guest-checkout requirement is not confirmed.

Not in this release
