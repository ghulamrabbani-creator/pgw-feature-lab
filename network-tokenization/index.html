Network Tokenization: saved-card payments with the scheme token

Visa charges a PAN Integrity Fee on card-not-present Visa payments that do not use a Visa network token. In the UAE the network token requirement for cards on file started on 18-Apr-2026 and the fee on 17-Oct-2026. Phase 1: every saved-card payment (CIT and MIT) through PGW goes out with the network token, and PGW records it on the transaction.

Two gateways, two different changes

The point to understand first. On MPGS the network token already works with today's PGW requests; PGW only has to record it. On CyberSource PGW sends the card number today, so PGW must pay differently: create an instrument identifier and pay with it.
MPGS · record only

The payment request does not change

  • PGW already pays CIT and MIT with the MPGS token.
  • With network tokens set up for the MID at MPGS, MPGS sends the network token by itself. Proven through PGW on 16–17 Nov for Visa and Mastercard.
  • New: PGW reads sourceOfFunds.type = SCHEME_TOKEN and records it (NT-M1 to NT-M5).
CyberSource · pay differently

PGW pays with an instrument identifier

  • Today PGW sends the card number on every CIT and MIT, so CYBS cannot use a network token.
  • New: create the instrument identifier at save card (NT-C1) and pay with it and networkTokenOption = prefer (NT-C3, NT-C4).
  • Proven in the 11-Nov POC and the 14-Nov test bench: Visa 015, Mastercard 014.

Both: new object transactions[].networkTokenDetails returned to the merchant (NT-0). One master toggle per MID, default OFF (Rule 1). Story map
