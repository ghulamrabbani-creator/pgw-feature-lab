Split modes

Each partner MID uses one split mode. The mode decides who defines the split, and when: the partner with each order, or Geidea once in the PGW configuration.

Illustrative Reflects product doc v1.6 and PGW stories v0.6 Read the requirement →
Terms: partner = the Geidea merchant (MID) with split payout on; vendor = a payee of the split, identified by an ID from APEX (the stories call it a Partner ID). Field names are from the PGW stories and can be renamed by PGW engineering.

The three modes side by side

Dynamic

The partner sends the split with each order, or later.

Who defines the split
Partner per order
Set up by Geidea in PGW
Vendor IDs only. No template.
Sent with the order
splitPayoutType + splitPayoutTransaction[], or deferredSplit = true, or nothing (normal payment)
Split after payment
Yes: Payout Advice API, NEW or UPDATE with legs
Typical use
Marketplace: several sellers in one checkout. Delivery platform: restaurant or store and the platform.
Try it in the simulator →

Fixed

One template, set by Geidea, applies to every order.

Who defines the split
Geidea once, for all orders
Set up by Geidea in PGW
Vendor IDs + one template (splitPayoutFixedTemplate)
Sent with the order
Nothing. Any split field is rejected.
Split after payment
No. The Payout Advice API rejects a Fixed MID.
Typical use
Standing revenue share: the same share of every sale goes to a supplier.
Try it in the simulator →

Profile

Geidea sets a catalog of templates; the partner picks one per order.

Who defines the split
Geidea defines the catalog, partner picks per order
Set up by Geidea in PGW
Vendor IDs + profile catalog (splitPayoutProfiles), up to 10 profiles
Sent with the order
splitPayoutProfileId, or deferredSplit = true. Legs are rejected.
Split after payment
Yes: Payout Advice API, NEW or UPDATE with a profile ID
Typical use
Aggregator with standard terms: an insurance aggregator with a pre-agreed split per insurer.

Rules for every mode

  • A leg names a vendor ID and a value. The value is an amount or a percentage of the gross transaction amount, never both.
  • All legs of one split use the same type: all amounts or all percentages.
  • Percentages are converted to amounts by APEX, not by PGW. Each amount is rounded to 2 decimals; the partner's residual absorbs the rounding difference.
  • Templates and profiles are configured by Geidea only. The partner has no access to split configuration.
  • A split carries vendor IDs and values only. Bank details always come from Geidea's records, never from the partner's request.
  • Maximum 10 legs per split (template, profile, or a split sent with an order or through the API). Configured as a system setting.
  • Amount legs are checked against the order amount at Create Session, not at setup: the order amount is not known when a template or profile is saved.

Source: product doc v1.6, 3.2 Rules common to all modes; stories SP-2 section 2, SP-4 section 2, SP-6 check 3.6.

Changing the mode or the set-up

Change saved in PGWEffect
Mode changedApplies to orders created after the save. The old mode's template or profiles stay stored but are not applied. Orders already created keep their split.
Template or profile editedApplies to orders created after the save. Orders already created keep the legs they were given.
Profile deletedNew orders with that profile ID are rejected.
Vendor ID deletedNew orders and API calls with that ID are rejected. Splits already sent to APEX do not change. A vendor ID used in the template or a profile cannot be deleted.
Split turned offNew orders with split fields and Payout Advice API calls are rejected. Orders already flagged stay flagged; APEX releases them after N days. Operations also turns split off in APEX.
